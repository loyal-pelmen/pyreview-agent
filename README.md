# Ревью Python-файла агентом

Перетащил файл `.py` на страницу — получил ревью: находки линтеров `ruff` и `ty`, логический разбор кода с привязкой к строкам и цепочку рассуждений агента. Модель — GigaChat, каркас агента — Deep Agents, бэкенд — FastAPI, страница — чистые HTML, CSS и JS.

## Цель

Дать разработчику первый проход ревью одного файла за минуту, без регистрации: файл ушёл, ответ пришёл, на сервере ничего не осталось.

## Что НЕ входит

- Хранение: нет базы, истории, учётных записей и сохранённых файлов. Файл живёт только на время запроса.
- Файлы кроме `.py` и больше одного файла за запрос; архивы, репозитории, PR.
- Правка кода за пользователя и скачивание исправленного файла.
- Фреймворки и сборка фронта: ни React, ни бандлера, ни CDN.
- Провайдеры моделей кроме GigaChat: поле `llm.provider` в конфиге зарезервировано, адаптер один.

Полные границы скоупа — `openspec/config.yaml`.

## Как это работает

1. Страница проверяет файл до отправки: расширение `.py`, один файл, размер не больше предела из `GET /api/v1/config`.
2. `POST /api/v1/review` проверяет файл ещё раз, кладёт его во временный каталог и собирает агента Deep Agents с моделью GigaChat.
3. Агент вызывает инструменты `run_ruff` и `run_ty` строго по одному за ход, читает код и разбирает логику: границы и индексы, формулы, исключения, `await` и блокирующие вызовы, утечки ресурсов, изменяемые значения по умолчанию.
4. Итог приходит структурированным ответом: вердикт, сводка, находки с номером строки и цитатой. Бэкенд сверяет номер строки по цитате, убирает повторы находок линтеров и обрезает список до предела.
5. Ответ — один JSON: ревью, находки линтеров, цепочка рассуждений, модель и расход токенов. Временный каталог удаляется при любом исходе.
6. Страница показывает код с подсветкой строк, находки, замечания линтеров и ленту рассуждений.

Контракт API — `openspec/notes/api-contract.md`.

## Запуск

### 1. Что нужно заранее

- macOS или Linux.
- `git`, `make`, `curl`.
- [uv](https://docs.astral.sh/uv/) — менеджер пакетов и окружений. Python 3.14 он скачает сам.

```
curl -LsSf https://astral.sh/uv/install.sh | sh
```

или на macOS `brew install uv`.

- Ключ GigaChat API. Его выдают в личном кабинете [developers.sber.ru](https://developers.sber.ru/studio): создайте проект GigaChat API и получите «Ключ авторизации». Это строка `base64(client_id:client_secret)`, её и нужно положить в `GIGACHAT_CREDENTIALS`.

### 2. Код и зависимости

```
git clone https://github.com/loyal-pelmen/pyreview-agent.git
cd pyreview-agent
make dev
```

`make dev` выполняет `uv sync --locked`: ставит Python 3.14, FastAPI, Deep Agents, `langchain-gigachat`, `ruff` и `ty` в `.venv` строго по версиям из `uv.lock`.

### 3. Сертификаты Минцифры

API GigaChat подписан цепочкой «Russian Trusted Root CA», которой нет в системных хранилищах. Без неё запрос к модели падает с `CERTIFICATE_VERIFY_FAILED`. Корневой и промежуточный сертификаты публикуются на Госуслугах, страница `https://www.gosuslugi.ru/crt`. Соберите из них один файл:

```
mkdir -p secrets/ca && cd secrets/ca
curl -O https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer
curl -O https://gu-st.ru/content/Other/doc/russian_trusted_sub_ca.cer
{ cat russian_trusted_root_ca.cer; echo; cat russian_trusted_sub_ca.cer; echo; } > russian_trusted_bundle.pem
cd ../..
```

Перевод строки между сертификатами обязателен: без него файл даёт ошибку `PEM lib`. Каталог `secrets/` в git не попадает.

### 4. Секреты в `.env`

```
cp .env.example .env
```

Заполните `.env`:

| Переменная | Значение |
|---|---|
| `GIGACHAT_CREDENTIALS` | ключ авторизации из личного кабинета |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` для физлица, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` для юрлица |
| `GIGACHAT_CA_BUNDLE_FILE` | путь к bundle из шага 3: `secrets/ca/russian_trusted_bundle.pem` |
| `CONFIG_PATH` | путь к конфигу, по умолчанию `config.json` |
| `LOG_LEVEL` | уровень лога, по умолчанию `INFO` |

Бэкенд читает `.env` сам при старте. Файл в git не попадает.

### 5. Конфиг модели `config.json`

Рабочий конфиг уже лежит в корне. Он читается один раз при старте, после правки нужен перезапуск. Неверный ключ или значение не дают приложению подняться, в логе будет имя поля.

| Ключ | Что задаёт | По умолчанию |
|---|---|---|
| `llm.provider` | провайдер модели, сейчас только `gigachat` | `gigachat` |
| `llm.model` | модель: `GigaChat-2` (Lite), `GigaChat-2-Pro`, `GigaChat-2-Max` | `GigaChat-2` |
| `llm.temperature` | случайность ответа, от 0 до 2 | `0.1` |
| `llm.max_tokens` | предел длины одного ответа модели | `4000` |
| `llm.timeout_seconds` | таймаут одного запроса к модели | `120` |
| `linters.ruff`, `linters.ty` | включён ли линтер; выключенный агенту не предлагается | `true` |
| `linters.timeout_seconds` | таймаут одного запуска линтера | `30` |
| `linters.ruff_select` | наборы правил `ruff` | `E F W B UP SIM C4 PL RUF` |
| `limits.max_file_bytes` | предел размера файла | `200000` |
| `limits.max_findings` | предел числа находок ревью | `30` |
| `limits.max_tool_calls` | предел вызовов инструментов за один анализ | `20` |
| `limits.analysis_timeout_seconds` | предел времени анализа | `300` |
| `limits.max_prompt_chars` | сколько символов кода уходит в промпт, остальное агент дочитывает инструментом | `60000` |
| `limits.max_tool_output_chars` | обрезка ответа инструмента | `4000` |
| `limits.max_lint_issues` | предел числа замечаний линтеров в ответе | `200` |

Секретов в `config.json` нет и быть не должно: ключи — только в `.env`.

### 6. Старт

```
make run
```

Откройте `http://127.0.0.1:8000` и перетащите файл `.py` в окно или нажмите «Выбрать файл». На GigaChat Lite файл в 40 строк разбирается за 3–10 секунд.

Проверить вид страницы без ключа и без запроса к модели: `http://127.0.0.1:8000/?demo`. Экран ожидания: `http://127.0.0.1:8000/?demo=progress`.

Тот же запрос из консоли:

```
curl -s -F file=@tests/fixtures/samples/buggy.py http://127.0.0.1:8000/api/v1/review | python3 -m json.tool
```

Служебные эндпоинты: `GET /healthz` — живость без обращения к модели, `GET /api/v1/config` — модель, включённые линтеры и пределы без секретов.

## Проверки

```
make lint       # ruff check, ruff format --check, ty check
make test       # pytest: линтеры, агент на фейковой модели, API
```

Тест с живым GigaChat помечен `integration` и по умолчанию пропускается. Запуск:

```
set -a; . ./.env; set +a
uv run pytest -m integration
```

CI в GitHub Actions выполняет `make lint` и `make test` на каждый push и PR.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `CERTIFICATE_VERIFY_FAILED` в логе, страница пишет «Модель сейчас не отвечает» | нет bundle сертификатов или неверный путь в `GIGACHAT_CA_BUNDLE_FILE`, см. шаг 3 |
| `PEM lib` в логе | сертификаты склеены без перевода строки, соберите bundle командой из шага 3 |
| `502 model_unavailable` сразу после отправки | неверный `GIGACHAT_CREDENTIALS` или `GIGACHAT_SCOPE`, либо закончились токены на ключе |
| приложение не стартует, в логе `config_invalid` | ошибка в `config.json`, имя поля указано в логе |
| `504 analysis_timeout` | файл слишком большой для модели; увеличьте `limits.analysis_timeout_seconds` или возьмите модель быстрее |
| порт 8000 занят | `uv run uvicorn pyreview.main:app --port 8001` |

## Качество ревью на GigaChat Lite

Lite быстрый и дешёвый, но нестабильный. На файле с намеренными ошибками три прогона из трёх нашли ошибку в формуле и выход за границу списка. Иногда Lite возвращает пустой список находок, поэтому бэкенд один раз переспрашивает модель. На чистом файле изредка бывает ложная находка. Серьёзность находок Lite ставит небрежно. Для более точного ревью поставьте в `llm.model` значение `GigaChat-2-Pro` или `GigaChat-2-Max`. Замеры — `openspec/notes/gigachat.md`.

## Состав

| Каталог | Что это |
|---|---|
| `src/pyreview/` | бэкенд: зоны `analysis` (агент, инструменты, сценарий ревью), `linters` (`ruff`, `ty`), `shared` (конфиг, ошибки, модель), `entrypoints` (FastAPI) |
| `frontend/` | страница: `index.html`, `styles.css`, `app.js` и пример ответа для демо-режима, отдаётся бэкендом как статика |
| `config.json` | модель, линтеры, пределы; секретов не содержит |
| `tests/` | тесты: образцы файлов, фейковая модель, тесты API и линтеров |
| `Rules/` | правила, требования, журнал решений |
| `openspec/` | контекст продукта, изменения, заметки о GigaChat и Deep Agents |

Инструкции для работы с кодом — `AGENTS.md` в корне, `src/AGENTS.md`, `frontend/AGENTS.md`, `Rules/AGENTS.md`. Нормы — `Rules/RULES.md`.
