## Context

Мотивация — `proposal.md`, поведение — `specs/`, контракт — `openspec/notes/api-contract.md`. Части пишутся параллельно против общих контрактов, которые в этом изменении не меняются: `shared/config.py` (`AppConfig`, `Settings`, `load_config`), `shared/errors.py` (`AppError` и пять наследников), `linters/domain.py` (`LintIssue`, `LintRun`), `linters/application.py` (порт `Linter`), `analysis/domain.py` (`SourceFile`, `Finding`, `Review`, `ReasoningStep`, `Usage`, `ModelInfo`, `ReviewReport`). Ограничения модели и каркаса, проверенные живым прогоном, — `openspec/notes/gigachat.md` и `openspec/notes/deepagents.md`.

## Goals / Non-Goals

**Goals:**
- Флоу «файл → ревью» целиком за один запрос, с пределами и понятными ошибками.
- Зоны собираются по фиксированным сигнатурам: `RuffLinter(select, timeout_seconds)`, `TyLinter(timeout_seconds)`, `build_chat_model(llm, settings)`, `ReviewService(config, linters, model_factory).review(name, data)`.

**Non-Goals:**
- Шаг 6 плана, потоковая лента, субагенты, второй провайдер — см. Non-goals в `proposal.md`.

## Decisions

### `ReviewService` — единственная точка сценария
Сервис проверяет файл, создаёт временный каталог, прогоняет включённые линтеры для поля `lint`, собирает агента, применяет пределы и строит `ReviewReport`; ошибки модели переводит в `ModelUnavailable`, общий таймаут — в `AnalysisTimeout`. Получаем: маршрут FastAPI тонкий, сценарий тестируется без HTTP с фейком модели через `model_factory`. Стоит: линтеры над файлом могут отработать дважды — для `lint` и по вызову агента; при `linters.timeout_seconds = 30` это приемлемо.

### Агент без лишних встроенных инструментов
`create_deep_agent` получает `FilesystemMiddleware` с `FilesystemBackend` над каталогом запроса и allowlist чтения — он заменяет встроенный по имени; субагент `general-purpose` выключен профилем каркаса под ключом `giga`, поэтому инструмента `task` нет (`openspec/notes/deepagents.md`). Получаем: у модели только чтение файла, `run_ruff`, `run_ty` и план, что закрывает `INV-04` и `INV-05`. Стоит: зависимость от бета-API профилей Deep Agents.

### Один вызов за ход — middleware обрезки
Перед исполнением middleware оставляет первый вызов инструмента хода, остальным отвечает `ToolMessage` с отказом и считает вызовы для `limits.max_tool_calls`. Получаем: GigaChat не падает на параллельных вызовах, предел соблюдается в одном месте. Стоит: модель тратит ход на повтор отброшенного вызова.

### Структурированный ответ и строки
`response_format` — модель pydantic итога с описаниями полей на русском; `GigaChat` создаётся с `allow_any_tool_choice_fallback=True`. Код передаётся модели пронумерованным листингом, находка несёт цитату строки, бэкенд выравнивает `line` по месту цитаты, затем отбрасывает строки вне диапазона в `dropped`. Получаем: находки стоят на верных строках при ошибке модели в номере. Стоит: листинг длиннее исходника, `limits.max_prompt_chars` наступает раньше.

### Цепочка рассуждений из следа
Шаги собираются из `result["messages"]` и поля рассуждения структурированного ответа; время шага — от начала анализа. Получаем: лента без второго запроса к модели. Стоит: `at_ms` у шагов одного хода совпадает.

### Страница с режимом `?demo`
Пример ответа лежит в `frontend/fixtures/sample-response.json` и отдаётся статикой; `?demo` рисует его без запроса на ревью. Получаем: проверка разметки руками без ключа GigaChat. Стоит: пример надо держать в соответствии с контрактом, а у страницы появляется файл сверх трёх.

## Инструменты агента

| Инструмент | Успех | Неверный аргумент | Превышение порога |
|---|---|---|---|
| `run_ruff`, `run_ty` (`{path}`) | строки `строка:столбец код сообщение` или «находок нет» | путь вне каталога, чужое имя или не та форма — строка с отказом, линтер не запускается | вывод обрезан до `limits.max_tool_output_chars` с пометкой; таймаут — строка о таймауте |
| `read_file`, `ls`, `grep` | содержимое из каталога запроса | ошибка бэкенда файлов строкой | ограничения каркаса |

## Внешние вызовы

- GigaChat: таймаут `llm.timeout_seconds`, повторов нет (`max_retries` по умолчанию `0`), отказ — `502`; весь анализ ограничен `limits.analysis_timeout_seconds` — `504`.
- `ruff`, `ty`: подпроцесс с таймаутом `linters.timeout_seconds`, без повторов; отказ одного линтера даёт агенту сообщение и не роняет запрос.
- Частичный отказ: превышение `max_tool_calls` завершает анализ с собранным и `usage.truncated = true`.

## Инварианты

- `INV-01`, `INV-03`: проверка файла до линтеров и модели, каталог удаляется в `finally`, лог без текста.
- `INV-02`: секреты только в `Settings` из окружения; в артефактах имена переменных.
- `INV-04`, `INV-05`: фиксированные аргументы линтеров, проверка пути, нет оболочки, записи и `task`.
- `INV-06`: имя модели и пороги только из `AppConfig`.
- `INV-07`, `INV-09`: ответ и ошибки по контракту, `/healthz` не трогает модель.
- `INV-08`, `INV-10`: выравнивание и отбрасывание строк, предел находок, вызовов и времени.
- `INV-11`: страница держит данные в памяти вкладки.

## Risks / Trade-offs

- [Модель — GigaChat Lite (`GigaChat-2`): быстрая, но нестабильная по качеству, замеры — `openspec/notes/gigachat.md`] → итог всегда добирается отдельным структурированным вызовом с одним повтором при пустом списке находок; смена модели — строка в `config.json`.
- [Бета-API профилей Deep Agents] → версия закреплена в `uv.lock`, поведение покрыто тестом на список инструментов.
- [Модель отвечает текстом вместо структуры] → `allow_any_tool_choice_fallback=True`, явное требование в промпте и запасной вызов `with_structured_output`; отказ запасного вызова — `502`.
