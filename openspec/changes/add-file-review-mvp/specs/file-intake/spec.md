## Purpose

Приём одного файла `.py` от страницы и его проверка до линтеров и модели, чтобы на анализ попадал только допустимый файл, а после ответа на сервере ничего не оставалось.

## ADDED Requirements

### Requirement: Один файл `.py` в UTF-8 в пределах размера
Бэкенд MUST принимать ровно один файл в поле `file` запроса `multipart/form-data`, с расширением `.py`, в UTF-8 и не больше `limits.max_file_bytes`, и отклонять остальное конвертом ошибки до запуска линтеров и первого обращения к модели.

Трассировка: `FR-U-02`, `FR-U-03`, `FR-U-04`, `FR-U-05`; блок приёмки 1.

#### Scenario: Допустимый файл принят
- **WHEN** приходит `app.py` в UTF-8 размером меньше `limits.max_file_bytes`
- **THEN** бэкенд запускает анализ и отвечает `200` с `file.name = "app.py"`, `file.bytes` и `file.lines`

#### Scenario: Файл не `.py`
- **WHEN** приходит `notes.txt`
- **THEN** ответ `400` с `error.code = "unsupported_file"`, линтеры и модель не вызываются

#### Scenario: Нет поля `file` или файлов больше одного
- **WHEN** запрос пришёл без поля `file` или с двумя файлами
- **THEN** ответ `400` с `error.code = "unsupported_file"`

#### Scenario: Файл слишком большой
- **WHEN** размер файла больше `limits.max_file_bytes`
- **THEN** ответ `413` с `error.code = "file_too_large"`, модель не вызывается

#### Scenario: Файл не в UTF-8
- **WHEN** содержимое `.py` не декодируется как UTF-8
- **THEN** ответ `422` с `error.code = "not_utf8"`, модель не вызывается

### Requirement: Пустой файл не тратит модель
Бэкенд MUST отвечать на пустой файл или файл из одних пробельных строк `200` с пустыми находками и итогом «проверять нечего», не обращаясь к модели.

Трассировка: `FR-U-06`; блок приёмки 1.

#### Scenario: Пустой файл
- **WHEN** приходит `empty.py` нулевой длины
- **THEN** ответ `200`, `review.verdict = "ok"`, `review.findings` пуст, `summary` говорит, что проверять нечего, `usage.tool_calls = 0`

### Requirement: Файл живёт только на время запроса
Бэкенд MUST держать присланный файл во временном каталоге, отдельном для каждого запроса, и удалять каталог при любом исходе запроса.

Трассировка: `NFR-02`, `NFR-05`, `INV-01`; блок приёмки 6.

#### Scenario: Каталог удалён после успешного ответа
- **WHEN** запрос завершился `200`
- **THEN** временного каталога запроса на диске нет

#### Scenario: Каталог удалён при ошибке
- **WHEN** анализ завершился `502` или `504`
- **THEN** временного каталога запроса на диске нет

#### Scenario: Параллельные запросы
- **WHEN** два запроса с разными файлами идут одновременно
- **THEN** каждый получает ответ по своему файлу, каталоги запросов различаются
