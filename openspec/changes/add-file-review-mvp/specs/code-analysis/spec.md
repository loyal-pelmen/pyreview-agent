## Purpose

Логический разбор файла агентом на GigaChat: находки с привязкой к строкам, итог и вердикт, видимая цепочка рассуждений и пределы, при которых анализ не роняет сервис.

## ADDED Requirements

### Requirement: Находки логических ошибок по строкам
Агент MUST искать логические ошибки из перечня `FR-R-01` и возвращать находки с `line`, необязательным `end_line`, `severity` из `bug` / `warning` / `nit`, `title`, `detail` на русском и необязательной `suggestion`; стиль и форматирование, которые ловит `ruff`, находками ревью не дублируются.

Трассировка: `FR-R-01`, `FR-R-02`, `FR-R-05`; блок приёмки 3.

#### Scenario: Изменяемое значение по умолчанию
- **WHEN** в файле `def add(item, bucket=[])` на строке 5
- **THEN** `review.findings` содержит находку с `line = 5` и объяснением на русском

#### Scenario: Только стилевые замечания
- **WHEN** в файле нет логических ошибок, а `ruff` нашёл длинные строки
- **THEN** находки `ruff` есть в `lint`, а `review.findings` их не повторяет

### Requirement: Строки находок в диапазоне файла
Бэкенд MUST оставлять в `review.findings` только находки со строкой в диапазоне `1..file.lines`, сортировать их по строке, ограничивать число `limits.max_findings` и учитывать отброшенные в `review.dropped`. Если находка цитирует код, строка выравнивается по месту цитаты в файле.

Трассировка: `FR-R-02`, `INV-08`; блок приёмки 3.

#### Scenario: Строка вне файла
- **WHEN** модель вернула находку со строкой 500 для файла из 120 строк и без цитаты, найденной в файле
- **THEN** находки нет в `review.findings`, `review.dropped` увеличен на 1

#### Scenario: Модель ошиблась номером строки
- **WHEN** модель указала строку 7, а процитированный код стоит на строке 9
- **THEN** находка в ответе стоит на строке 9

#### Scenario: Находок больше предела
- **WHEN** модель вернула находок больше `limits.max_findings`
- **THEN** в ответе ровно `limits.max_findings` находок, остаток учтён в `review.dropped`

### Requirement: Итог и вердикт
Ревью MUST содержать `summary` на 2–5 предложений и `verdict`: `issues`, если есть находки серьёзности `bug` или `warning`, иначе `ok`.

Трассировка: `FR-R-03`; блок приёмки 3.

#### Scenario: Чистый файл
- **WHEN** агент не нашёл проблем
- **THEN** `verdict = "ok"`, `findings` пуст, `summary` не пуст

### Requirement: Цепочка рассуждений
Ответ MUST содержать `reasoning` — упорядоченные шаги с `n`, `at_ms` от начала анализа и `kind` из `thought`, `tool_call`, `tool_result`, `conclusion`; вызов несёт имя инструмента и аргументы, результат — текст не длиннее 2000 символов с флагом `truncated`.

Трассировка: `FR-R-04`, `NFR-06`; блок приёмки 3.

#### Scenario: Вызов линтера виден в ленте
- **WHEN** агент вызвал `run_ruff`
- **THEN** в `reasoning` есть шаг `tool_call` с `tool = "run_ruff"` и `args`, за ним шаг `tool_result` того же инструмента

#### Scenario: Последний шаг — вывод
- **WHEN** анализ завершён структурированным ответом
- **THEN** последний шаг `reasoning` имеет `kind = "conclusion"`

### Requirement: Один вызов инструмента за ход
Анализ MUST выполнять не больше одного вызова инструмента за ход модели; лишние вызовы того же хода не исполняются и не роняют запрос.

Трассировка: `FR-R-04`, `INV-09`; блок приёмки 3.

#### Scenario: Модель вызвала два инструмента за ход
- **WHEN** модель в одном ходе вернула вызовы `run_ruff` и `run_ty`
- **THEN** исполняется только `run_ruff`, модель получает отказ по второму вызову, ответ `200`

### Requirement: Пределы анализа
Анализ MUST останавливаться по `limits.max_tool_calls` с тем, что собрано, и по `limits.analysis_timeout_seconds` с ошибкой; код в промпте обрезается до `limits.max_prompt_chars`.

Трассировка: `NFR-01`, `NFR-06`, `INV-10`; блоки приёмки 3, 6.

#### Scenario: Превышен `max_tool_calls`
- **WHEN** модель пытается вызвать инструменты больше `limits.max_tool_calls` раз
- **THEN** анализ завершается с собранным, ответ `200` с `usage.truncated = true`, `summary` говорит об обрыве

#### Scenario: Таймаут анализа
- **WHEN** анализ не уложился в `limits.analysis_timeout_seconds`
- **THEN** ответ `504` с `error.code = "analysis_timeout"`

#### Scenario: Длинный файл
- **WHEN** текст файла длиннее `limits.max_prompt_chars`
- **THEN** модель получает обрезанный код, и обрезка видна в `reasoning`

### Requirement: Недоступность модели
Отказ GigaChat MUST давать на ревью `502 model_unavailable` и не ронять сервис.

Трассировка: `NFR-04`, `INV-09`; блок приёмки 6.

#### Scenario: GigaChat недоступен
- **WHEN** GigaChat не отвечает или отвергает авторизацию
- **THEN** ответ `502` с `error.code = "model_unavailable"`, `GET /healthz` отвечает `200`
