# Ограничения GigaChat

Справочная заметка: как подключается модель и чего от неё ждать нельзя. Сверено 29.10.2026 по документации `langchain-gigachat` и GigaChat API через context7, дополнено 30.10.2026 по исходникам `langchain-gigachat` 0.5.1 и живому прогону. Нормы проекта — `Rules/RULES.md`, здесь только внешние ограничения.

## Подключение

- Пакет `langchain-gigachat`, класс `langchain_gigachat.GigaChat`. Без аргументов читает `GIGACHAT_CREDENTIALS` (ключ авторизации OAuth, это `base64(client_id:client_secret)`) и `GIGACHAT_SCOPE`: `GIGACHAT_API_PERS` у физлица, `GIGACHAT_API_B2B` и `GIGACHAT_API_CORP` у юрлица. Модель — `GIGACHAT_MODEL`.
- Модели, доступные на ключе проекта по `GET /models` 29.10.2026: `GigaChat-2`, `GigaChat-2-Max`, `GigaChat-2-Pro`, `GigaChat-3-Lightning`, `GigaChat-3-Pro`, `GigaChat-3-Ultra` и эмбеддинги. Владелец выбрал GigaChat Lite 30.10.2026: в API это `GigaChat-2` (или `GigaChat`), Pro — `GigaChat-2-Pro`, Max — `GigaChat-2-Max`; соответствие подтверждено тарифами на `developers.sber.ru`. Переход на другую модель — правка `llm.model` и прогон набора `integration`.
- Сертификаты: API подписан цепочкой Минцифры, которой нет в системных хранилищах; без bundle с корневым и промежуточным сертификатом TLS не проходит. Путь к bundle — `GIGACHAT_CA_BUNDLE_FILE`, как его собрать — `README.md`. `verify_ssl_certs=False` допустим только в разработке и в код не попадает.
- `ls_provider` у `GigaChat` — `giga`: имя класса без `Chat`. По этому ключу Deep Agents ищет профиль каркаса (`openspec/notes/deepagents.md`).
- Токен доступа выпускается SDK сам по ключу и живёт 30 минут; обновляется без участия кода.
- `max_retries` у SDK по умолчанию `0`; повторы на `429`, `500`, `502`, `503`, `504` включаются `max_retries` с `retry_backoff_factor`. Не сочетать с `.with_retry()` LangChain — попытки перемножаются.

## Вызов инструментов

- Инструменты передаются через `bind_tools`; Deep Agents делает это сам. Описание обязательно: у функции под `@tool` — docstring, у модели pydantic аргументов и структурированного ответа — описания модели и полей. Без них GigaChat выбирает инструмент и заполняет поля наугад.
- `tool_choice="any"` не поддерживается: `ValueError`, если не включён `allow_any_tool_choice_fallback`. `response_format` в Deep Agents требует именно этот режим, поэтому `GigaChat` создаётся с `allow_any_tool_choice_fallback=True`.
- **Параллельных вызовов нет.** `AIMessage` с двумя и более `tool_calls` вызывает `ValueError` в `langchain-gigachat`. Промпт просит один инструмент за ход, а middleware обрезки оставляет первый вызов и возвращает модели остальные сообщением об отказе, чтобы запуск не падал.
- Параметр `extras={"few_shot_examples": [...]}` у `@tool` даёт модели примеры вызова — полезно для инструментов с путями файлов.
- `function_ranker` включён по умолчанию и сам выбирает подмножество инструментов; при пяти-шести инструментах его можно выключить `{"enabled": False}`, чтобы модель видела все.

## Контекст и вывод

- Окно контекста у `GigaChat-2-Max` и `GigaChat-2-Pro` — 128 тысяч токенов; код в промпте и вывод линтеров обрезаются до порога заранее (`NFR-06`). Подсчёт токенов без API — `len(text) / 4.6`, через API — `use_api_for_tokens=True`.
- Структурированный ответ через вызов функции работает; модель pydantic находки — единственный способ получить строку без разбора текста.
- Модель ошибается в номерах строк. Помогают пронумерованный листинг кода в промпте и цитата строки в находке: бэкенд выравнивает номер по месту цитаты в файле.
- Модель склонна отвечать текстом вместо вызова инструмента, если промпт не требует вызова явно; промпт просит сначала собрать данные инструментами, потом вернуть структурированный итог.
- Скорость 30.10.2026: файл в 23 строки на `GigaChat-2-Max` — около 18 с; файл в 39 строк на `GigaChat-2` (Lite) — 3–10 с и 1,8–3,2 тысячи токенов.
- Поведение Lite (`GigaChat-2`), замеры 30.10.2026:
  - линтеры вызывает исправно и по одному за ход;
  - разбор пишет текстом в одном сообщении с маркерами `think:` вместо вызова инструмента `think` и почти никогда не сдаёт итог через `ReviewDraft`, поэтому итог всегда приходит из отдельного вызова `with_structured_output`; маркеры `think:` режутся на отдельные шаги цепочки;
  - отвечает по-английски, если промпт и описания полей не на русском;
  - иногда сдаёт `issues` с пустым списком находок или `ok` на файле с ошибками; помогает один повторный запрос: «перечисли каждую проблему отдельной находкой» или «проверь ещё раз по списку»;
  - на файле с намеренными ошибками три прогона из трёх нашли формулу и выход за границу; на чистом файле один прогон из трёх дал ложную находку про синтаксис дженериков Python 3.12;
  - серьёзность и регистр букв в заголовках ставит небрежно.
- Модерация включена: `profanity_check` фильтрует ответ, на коде это не сказывается.
