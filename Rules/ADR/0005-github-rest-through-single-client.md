# 0005 — GitHub REST через единственный клиент на httpx

Тип: решение
Статус: заменено 0006, 29.10.2026

## Контекст

Агенту нужно читать PR, дифф, список файлов и обзоры и публиковать обзор — пять эндпоинтов REST. Токен GitHub — секрет, и он не должен оказаться в аргументах инструмента или в промпте. Модели нельзя давать произвольный HTTP.

## Решение

Один класс `GitHubClient` в `github/infrastructure/` на `httpx.AsyncClient` с базовым адресом из настройки и заголовками `Authorization: Bearer`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version`. Дифф запрашивается тем же клиентом с `Accept: application/vnd.github.diff`. Ответы разбираются моделями pydantic на границе и отдаются внутрь датаклассами. Инструменты агента зовут порт `PullRequests`, а не клиент; токен живёт только в клиенте. `429` и `403` с исчерпанным лимитом ждут `Retry-After` или `X-RateLimit-Reset` до трёх попыток, `5xx` повторяются с экспоненциальной паузой, остальное — ошибка запуска.

## Альтернативы

- **PyGithub** — отклонено: синхронный, тянет зависимости и прячет форму ответа; дифф всё равно пришлось бы брать отдельным запросом.
- **`gh` CLI подпроцессом** — отклонено: зависимость от установленного бинаря и его авторизации на машине, труднее тестировать.
- **GraphQL** — отклонено: дифф и публикация обзора с комментариями к строкам в REST проще, а объём данных мал.

## Последствия

- Тесты GitHub — respx поверх фикстур ответов в `tests/fixtures/github/`; живой API только под `integration`.
- Новый запрос к GitHub — метод клиента и порт; других HTTP-клиентов в коде нет (`INV-03`).
- Смена хостинга — новый адаптер того же порта; сейчас вне скоупа.
