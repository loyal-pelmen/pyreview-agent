# 0004 — Один обзор с комментариями к строкам, идемпотентный по `SHA`

Тип: решение
Статус: заменено 0006, 29.10.2026

## Контекст

GitHub даёт три способа оставить замечание в PR: комментарий к PR целиком, одиночный комментарий к строке и обзор, в котором тело и комментарии к строкам приходят одним запросом. Агент запускается повторно — по расписанию или вручную, — и каждый запуск не должен плодить дубликаты. Комментарий к строке GitHub принимает только на строку из диффа и отвечает `422` на любую другую.

## Решение

Один обзор на запуск: `POST /repos/{owner}/{repo}/pulls/{n}/reviews` с `event: COMMENT`, телом и массивом `comments[]` по `path`, `line`, `side`. Тело обзора начинается с маркера `<!-- pr-review sha=<head_sha> -->`; перед публикацией агент читает обзоры PR, и если маркер с той же `SHA` уже есть, не публикует ничего и завершается кодом `0`. Находка на строку вне диффа и находки сверх `REVIEW_MAX_COMMENTS` переносятся в тело обзора списком. Обзор публикуется одним запросом после того, как модель закончила: частичный обзор не уходит.

## Альтернативы

- **Одиночные комментарии к строкам по мере находок** — отклонено: несколько запросов, часть которых может упасть, и нет одного места для итога.
- **Комментарий к PR целиком без привязки к строкам** — отклонено: ревьюер не видит, о какой строке речь.
- **Обзор `REQUEST_CHANGES` при находках серьёзности `bug`** — отклонено: агент не блокирует слияние, решение за человеком (`INV-01`).
- **Обновлять прежний обзор вместо нового** — отклонено: GitHub не даёт редактировать комментарии к строкам обзора пакетно; новая `SHA` — новый обзор.

## Последствия

- Повторный запуск на той же голове — пустая операция; новый коммит в PR — новый обзор рядом со старым.
- Карта строк диффа строится до вызова модели и отдаётся ей инструментом: модель знает, куда можно ставить комментарий.
- Отказ GitHub на публикации — код выхода `2` и обзор в логе, чтобы его не потерять.
- Режим `--dry-run` печатает тот же обзор в консоль, не трогая GitHub.
